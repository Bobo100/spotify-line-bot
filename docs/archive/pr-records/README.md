# 改動紀錄 (docs/plan)

每個 PR 一份紀錄，檔名 `YYYY-MM-DD-<topic>.md`，跟程式碼放在同一個 PR。

檔名開頭是日期，照檔名排序就是時間順序，所以不另外維護索引（多個 PR 同時開時，共用的索引一定會衝突）。紀錄也不寫狀態，PR 是否 merge 看 GitHub 上的 PR 頁面。

## 範本

段落固定是下面 8 個，順序和標題都不改；沒有內容的段落寫「無」，不要刪掉。

```markdown
# <標題，跟 PR 標題的摘要一致>

- 日期：YYYY-MM-DD
- Branch：`<branch>`
- PR：#<number>（開 PR 後補上）

## 背景
為什麼要做這件事。

## 計畫
- [ ] 步驟一
- [ ] 步驟二

## 實際改動
做完後補上：改了哪些檔案、各做了什麼。

## 和計畫不同的地方
實作或 code review 後改變的地方，以及原因。

## 驗證
做了哪些檢查、結果如何；還沒做的（例如在 LINE 上實測）也寫出來。

## 影響與注意事項
Breaking change、需要新增的環境變數、使用者要重新登入、部署步驟、已知限制等。

## code review 中不處理的項目
review 提出但沒修的項目，各自寫原因。

## 後續待辦
這次發現、但不在這個 PR 處理的問題。
```
